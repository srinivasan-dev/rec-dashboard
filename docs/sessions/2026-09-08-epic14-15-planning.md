**Shipped:** see `CHANGELOG.md` "[Unreleased] - 2026-09-08 - Backlog: API Docs & Authentication
Planning". Planning only — no source code changed this session.

## Decisions & why

- **Scoped this session to planning, not implementation**, per the user's literal request
  ("update the plan and the backlog... epic user story and tasks"). Two new epics were added to
  `docs/backlog/` with real acceptance criteria, not just placeholder names, but no `apps/api` or
  `apps/web` code was touched.
- **Two separate epics, not one**, because they're different concerns with different trust
  boundaries: EPIC-14 (Swagger/OpenAPI docs, gated by HTTP Basic Auth) is about the API's
  documentation surface; EPIC-15 (a real login for the dashboard) is about the actual
  merchant-isolation boundary CLAUDE.md treats as non-negotiable. Conflating them risked implying
  Basic Auth on the docs route is an acceptable substitute for real merchant authentication on
  the data endpoints — it explicitly is not (see EPIC-14's task list: Basic Auth deliberately
  does not gate `/api/reconciliation/*`).
- **EPIC-15 is framed as implementing an already-documented seam, not inventing new scope.**
  `docs/architecture.md` §4 already stated `attachMerchantContext`'s mock is "standing in for a
  real session/token layer" and named the exact swap point. EPIC-15's tasks point directly at
  that seam rather than proposing a parallel auth mechanism.
- **Stated the security floor explicitly in the backlog itself**, not just in this log: passwords
  never stored in plaintext, and `merchantId` still never trusted from client input post-login —
  "simple" describes the login's feature surface (no SSO, no password reset, no MFA), not a
  license to weaken the one non-negotiable this whole codebase is built around.
- **EPIC-14 and EPIC-15 tracked as their own new epics/rows**, not folded into any already-"done"
  phase's numbers — the same treatment EPIC-EX got when engineering-standards work was added
  mid-build. Keeps scope growth after the original 13-phase plan visible in the tracker rather
  than quietly rewritten into history.
- **Found and fixed a real backlog drift bug while in these files**: `docs/backlog/epics.md`,
  `user-stories.md`, and `tasks.md` had not been updated since Phase 7 — EPIC-08 through EPIC-13
  still showed "Not Started" despite all being completed and marked Done in
  `docs/project-plan.md` since Phase 13. Corrected all three files' statuses and backfilled
  `tasks.md`'s coarse "refine at phase start" placeholders for EPIC-08–13 with real task
  breakdowns reconstructed from the corresponding session logs and CHANGELOG entries. This wasn't
  requested directly, but leaving a reviewer-facing backlog folder contradicting the project-plan
  tracker sitting right next to it would have been a real, avoidable inconsistency to find
  mid-review.
